# tests/golden

감속 곡선 / 펄스 시퀀스의 골든 스냅샷이 여기 쌓인다. `*.test.ts` 는 vitest 가 함께 수집한다.

**스냅샷은 "테스트가 실패하니까" 갱신하지 않는다** (CLAUDE.md 불변식 8).
물리 튜닝으로 의도적으로 바꾼 경우에만 갱신하고, 사유를 커밋 메시지에 남긴다.

## 구성

| 파일                 | 역할                                                                          |
| -------------------- | ----------------------------------------------------------------------------- |
| `scenario-runner.ts` | 시나리오 정의 + 실행기. **기준값 생성과 검증이 같은 코드를 쓴다.**            |
| `spindown.test.ts`   | JSON 기준값과 현재 물리를 비교한다.                                           |
| `spindown-*.json` 등 | 기준값. `constants` / `scenario` / `totals` / `samples[[t, ω, θ], ...]` 구조. |

각 JSON 은 만들어질 당시의 물리 상수를 통째로 박아둔다. 상수를 건드리면 곡선이 어긋나기 전에
`constants` 비교에서 먼저 걸리므로, 실패 메시지만 보고도 원인이 "상수 변경"임을 알 수 있다.

## 왜 vitest 스냅샷(`toMatchSnapshot`)이 아니라 JSON 인가

- 기준값이 사람이 읽는 (t, ω, θ) 표로 남는다. diff 에서 "얼마나" 달라졌는지 바로 보인다.
- `-u` 플래그 한 번에 전부 덮어써지는 경로가 없다. 갱신은 아래의 명시적 절차뿐이다.

## 부동소수 비교

**허용오차 없이 정확히(`Object.is`) 비교한다.** `physics.ts` 는 `+ - * /` 와
`Math.abs / sign / min / max` 만 쓰고, 이들은 IEEE-754 로 결과가 규정된 연산이라
windows 로컬과 ubuntu CI 에서 비트 단위로 같은 값이 나온다. (`Math.hypot` 같은
정확도 미규정 함수를 쓰기 시작하면 이 보장이 깨진다 — core 에서 쓰지 않는다.)
허용오차를 두면 "미세하게 다른 물리"가 조용히 통과하므로 두지 않는다.

## 갱신 절차 (의도적 변경일 때만)

```bash
FIDGET_UPDATE_GOLDEN=1 npx vitest run tests/golden
npm run format          # 생성된 JSON 을 prettier 형식으로 정리
git diff tests/golden   # 전후 수치를 눈으로 확인한다
```

- CI(`CI` 환경변수)에서는 이 플래그가 **에러로 막힌다.** CI 가 기준값을 새로 쓰면
  테스트는 아무것도 지키지 않는 무의미한 통과가 되기 때문이다.
- 커밋 메시지에 **무엇을 왜 바꿨는지 + 전후 수치**를 적는다. 물리 상수를 바꾼 경우
  `DECISIONS.md` 에 ADR 도 남긴다.
